1. Check your installed firmware

On the PS5 home screen, open the following menu and write down the system software version:

  1. Settings
  2. System
  3. System Software
  4. Console Information

Keep your current firmware. Match the complete version to one of the exact lists below; a range does not include every possible version inside it.

UMTX21.00–5.50Browser route. No Blu-ray drive required.↗BD-J + UMTX6.00–7.61Disc route. Requires a working Blu-ray drive, writer and recordable disc.↗Relapse7.00–13.60Browser route on the listed versions. Excludes 9.05, 10.60 and 11.40.↗

On listed 7.xx firmware, the Blu-ray and Relapse routes overlap. Choose one entry method. Firmware absent from all three lists has no confirmed route in this guide.

2. Prepare your console

  • Keep a backup of important saves before starting. Do not select an update, reinstall or factory reset as a jailbreak step.
  • Use a stable Wi-Fi or wired connection. A computer sending a JAR or ELF needs to reach the PS5 on the same local network.
  • Browser methods need a working browser entry or User’s Guide redirect. A shortcut PKG cannot bootstrap a stock console because installing it already requires homebrew access.
  • For the disc method, prepare the matching JAR Loader v4.1.1 files, a Blu-ray writer and BD-R or BD-RE media.

Browser access and DNS

Open your existing browser entry, or use the instructions supplied by your chosen User’s Guide DNS host. On PS5, connection settings are under Settings → Network → Settings → Set Up Internet Connection; select your connection and open Advanced Settings to change DNS.

One documented User’s Guide entry

For the public entry documented by the project below, use Manual DNS with primary 62.210.38.117 and leave secondary DNS blank. Open Settings → User’s Guide, Health & Safety, and Other Information → User’s Guide. Some system versions label this menu Guide & Tips.

If the redirected host shows a Type URL control, enter https://speedy-away.github.io/hosts/ps5/ there, then select your exact firmware. This is a browser-entry option, not a firmware unlock. The DNS service and its menu can change; if the redirect or Type URL control is absent, use your host provider’s documented browser entry instead.

  • Public User’s Guide DNS and Type URL instructions

DNS changes alone do not jailbreak the console or guarantee update blocking. Restoring DNS to Automatic can allow update connections again. PSN sign-in has its own firmware requirements; using a modified console online can risk account or console suspension.

3. UMTX2 · browser walkthrough

Use this route only on the following UMTX2 builds. The browser chain stops at 5.50, even though the underlying UMTX vulnerability has a wider range.

Exact supported firmware

1.00, 1.01, 1.02, 1.05, 1.10, 1.11, 1.12, 1.13, 1.14, 2.00, 2.20, 2.25, 2.26, 2.30, 2.50, 2.70, 3.00, 3.10, 3.20, 3.21, 4.00, 4.02, 4.03, 4.50, 4.51, 5.00, 5.02, 5.10, 5.50

  1. Open the matching UMTX2 entryOpen the PS5 host, select your exact installed firmware and choose UMTX2. Check the firmware reported by the page before continuing. Stop if it reports an unsupported version.
  2. Start the normal Jailbreak optionChoose Jailbreak for initial kernel access. Webkit-only (sender) mode is for a loader that is already running; it does not start the kernel chain.
  3. Wait for the payload screenLet the page finish its progress and any automatic retry. A browser error, freeze or restart is not a successful result.
  4. Read the listening addressThe build attempts to start the ELF loader on TCP port 9021. Its older-payload loader uses port 9020 and is unavailable in Webkit-only mode. Read the displayed address and any loader errors.
  5. Load one supported payloadChoose a payload from the menu, or use a compatible sender with the displayed address and port. Check the payload’s exact firmware support, then wait for its own completion message.

4. Blu-ray · JAR Loader walkthrough

This route uses BD-J and UMTX on the following firmware. It needs a working, enabled PS5 Blu-ray drive, a computer with Java 11, a Blu-ray writer and recordable media.

Exact supported firmware

6.00, 6.02, 6.50, 7.00, 7.01, 7.20, 7.40, 7.60, 7.61

ps5-jar-loader-4.1.1.iso umtx1-1.0-SNAPSHOT.jar jailbreak-1.0-SNAPSHOT.jar
  1. Prepare the v4.1.1 filesUse ps5-jar-loader-4.1.1.iso, umtx1-1.0-SNAPSHOT.jar and jailbreak-1.0-SNAPSHOT.jar from the same official release. The Full ISO contains an older UMTX copy; v4.1.1 requires sending the updated UMTX through Remote Loader.
  2. Burn the ISO as a disc imageUse your Blu-ray writing software’s image-writing option, select the ISO and a BD-R or BD-RE disc, then finish disc verification. Copying the ISO file onto a data disc is not the same operation.
  3. Start the loader on PS5Insert the disc, open Media and launch Disc Player / PS5 JAR Loader. Start its Remote Loader and wait for the listening screen. The default JAR port is 9025.
  4. Find the PS5’s local IPOpen Settings → Network → Connection Status → View Connection Status and note the IPv4 address. Keep the computer and PS5 on the same local network.
  5. Send the updated UMTX1 JAROn the computer, run the first command below, replacing <PS5_IP> with the console’s local address. Wait for UMTX completion before sending another JAR.
  6. Send the process-jailbreak JARRun the second command after UMTX succeeds. This grants the BD-J process root privileges and escapes its /app0 filesystem jail. Check the console output before continuing.
java -jar umtx1-1.0-SNAPSHOT.jar <PS5_IP>java -jar jailbreak-1.0-SNAPSHOT.jar <PS5_IP>

This workflow establishes kernel read/write and a privileged BD-J process. Kernel-data writes are restricted on 6.00 and later. Check the exact ELF loader, HEN and app requirements separately before loading anything else.

5. Relapse · browser walkthrough

Relapse covers the exact versions below on retail consoles and testkits. Devkits use a separate upstream build. Firmware 9.05, 10.60 and 11.40 is not supported by this build.

Exact supported firmware

7.00, 7.01, 7.20, 7.40, 7.60, 7.61, 8.00, 8.20, 8.40, 8.60, 9.00, 9.20, 9.40, 9.60, 10.00, 10.01, 10.20, 10.40, 11.00, 11.20, 11.60, 12.00, 12.02, 12.20, 12.40, 12.60, 12.70, 13.00, 13.20, 13.40, 13.42, 13.60

  1. Open the Relapse entryUse your browser entry or User’s Guide redirect, open the PS5 host and select the Relapse option for your exact firmware.
  2. Let the run page completeLeave the page open while the exploit runs. A successful run displays its payload menu in the same page. If it fails or restarts, follow the recovery guidance below before retrying.
  3. Use the run page’s payload menuSelect one payload whose release explicitly supports your firmware. The menu sends ELF files to the console’s own loader on 127.0.0.1:9021.
  4. Check the payload resultWait for the payload’s own completion or listening message. Exploit support does not guarantee that etaHEN, an installer or every other homebrew payload supports the same firmware.

On static hosts, use the payload menu on the run page. The separate elf.html menu expects an already jailbroken console and a network-reachable backend; it does not work by itself on GitHub Pages.

Confirm the exploit result and the selected payload result separately. If you plan to use homebrew, first check its firmware and loader requirements. Start with one working payload before adding plugins, stores or other apps.

7. Troubleshooting

Unsupported firmware
Read the full version again and check the exact list for your chosen method. Changing DNS, changing a selector or loading a different payload does not add missing firmware support.
Browser error, freeze or restart
Do not count the attempt as successful. Let the console complete any normal recovery, then retry the matching entry instructions. Avoid interrupting a storage check or powering off while data is being written.
Computer cannot send a payload
Check the displayed console IP, the required port, the local network and the running loader. JAR Loader uses 9025; UMTX2’s ELF loader uses 9021, with 9020 for its older loader. These are different services.
Exploit succeeds but an app does not
Check that app’s release notes and firmware support. A working exploit or loader is only the first requirement. Confirm the expected HEN, plugin and package format before retrying.
