Xbox One / Series Dev Mode

Activate Microsoft Developer Mode, connect over your LAN and install native Xbox UWP apps. Includes model-specific downloads, dependencies and save-folder setup.

Set up Dev ModePC
ActivateDevice PortalInstall appsNative appsDependenciesStorageRetail ModeXbox 360Game downloads

Start with your console

Activate once, connect over your LAN, then install the matching native UWP build.

One, One S or One X

Use Xbox One compatible x64 UWP packages. For XBSX2 select SSE4. Expect tighter emulator performance limits than on Series consoles.

Series S or Series X

Use the Series build where offered. For XBSX2 select AVX2. Performance depends on the app and game; Dev Mode does not grant unrestricted hardware access.

What you need

A retail console, controller, internet for activation, a registered developer account, and a computer with a browser on the same LAN. USB storage is optional and app-specific.

This is Microsoft’s retail Developer Mode route. Retail games and Store apps run in Retail Mode; sideloaded development apps run in Dev Mode. No physical console installation or performance testing was performed for this page.

1 · Register & activate

  1. Create or check your developer accountNew users should start at Microsoft Store developer registration . Microsoft’s account page, updated 29 October 2026, says the new Individual and Company flow has no registration fee. Individual registration uses a personal Microsoft account, government ID and selfie. Complete verification and reach the Partner Center Apps & Games workspace. Existing fully registered accounts can be reused.
  2. Install Xbox Dev Mode on the consoleIn the console Microsoft Store, find the Microsoft-published Xbox Dev Mode app. Open it and note the activation code. Keep the console connected while activation completes.
  3. Register the displayed codeOn your computer sign into the same registered app-developer account and open Manage Xbox development consoles . Enter the code shown on your own console and review Microsoft’s activation agreement. A normal Microsoft account without completed developer enrollment is insufficient.
  4. Switch and restartAfter successful activation choose Switch and restart in Xbox Dev Mode. Developer Home opens in the development environment. Keep a console user signed in when deploying apps.

Microsoft warns that direct Xbox / Partner Center links may still enter the legacy registration flow. Begin new enrollment at storedeveloper.microsoft.com and check the current account page if a fee or verification screen differs. No fee is collected by this site.

  • Microsoft: current developer-account registration
  • Microsoft: console activation and mode switching

2 · Open Device Portal over your LAN

  1. Find Developer HomeDev Home shows the console’s name, IP address and OS version. Keep the computer and console on the same local subnet; wired Ethernet is useful for large transfers.
  2. Enable remote accessIn Dev Home open Home → Remote Access Settings. Enable Xbox Device Portal, set a username and password, and save. Read the Remote Access URL shown on that console.
  3. Connect from your computerOpen the displayed URL in a browser. The usual form is https://<console-system-IP>:11443. Check the address matches your console before handling its console-generated certificate warning. Sign in using the Remote Access username and password.
  4. Use the correct credentialsThe Developer Home “Show Visual Studio pin” action is for Visual Studio pairing. Browser access uses the Remote Access login. Visual Studio and the Windows SDK are not required just to upload these prepared packages through Portal.
  • Microsoft: Developer Home controls
  • Microsoft: enable Xbox Device Portal
  • Microsoft: current Xbox HTTPS endpoint and port 11443

3 · Install an app & its x64 dependencies

  1. Download the matching console packageChoose your model in the catalogue below. Download the native APPX / MSIX or bundle and the listed x64 frameworks to your computer. The extracted PPSSPP MSIX and DurangoFTP APPX bundle are ready for Portal; their original ZIPs remain available separately.
  2. Open the Portal app installerOn the Device Portal Home / Apps area, use Add or Install app. Choose the APPX, MSIX, APPX bundle or MSIX bundle as the main package. A ZIP must be extracted first. Follow the portal prompts for the publisher certificate if it requests one.
  3. Attach the required frameworksChoose each required x64 APPX under dependency packages, then install. The catalogue lists the exact manifest identities and minimum versions. Existing matching frameworks at the required version or newer can be reused. Microsoft.VCLibs.140.00.UWPDesktop is a different framework from Microsoft.VCLibs.140.00.
  4. Wait for installation, then launchWait for Portal to report success. Launch the app from Developer Home → Games & apps. Where the publisher requires it, use the app’s options / details to set App type to Game before launch. For emulators, select the required BIOS, game and save folders inside the app.
  5. Read failures before retryingFor dependency errors, compare Name, Publisher, version and x64 architecture with the package details. For minimum-OS errors, read your Dev Home OS version against that specific build. Do not substitute a desktop EXE, x86 app or Store-submission .appxupload wrapper.
  • Microsoft: manual sideloading with dependencies
  • Microsoft: Device Portal app installation and removal

Storage, USB paths & save backups

  1. Keep app data separate from the installed packageUse Device Portal File explorer to select the installed app’s local storage. Apps can store data in LocalState or LocalCache; follow the path on the app card. Kodi uses LocalCache\Roaming\Kodi. Package identities are listed on the cards so similarly named apps can be distinguished. Back up saves and configuration before uninstalling or moving to a different package identity.
  2. Choose real folders in each appUSB drive letters vary; use the app’s picker and check the actual mounted drive. The catalogue’s folders are examples. There is no SD-card layout or shared mandatory USB path for Xbox Dev Mode.
  3. Prepare external storage for the chosen emulatorThe XBSX2 publisher guide calls for NTFS and ALL APPLICATION PACKAGES access permissions when preparing the drive on Windows. Follow its exact permission steps and choose BIOS / game / memory-card folders in XBSX2. Do not reformat a drive containing the only copy of your data. Other apps have their own folder and access requirements.
  4. Check available development storageUse the storage information shown by your console and Portal. No universal free-space quota is promised here. ROMs, optional NAND / BIOS files, textures and save states can consume much more space than the app download.
  • Microsoft: package-specific LocalAppData file access
  • XBSX2 publisher: USB formatting, permissions and directory choices

Remove apps or return to Retail Mode

  1. Remove one appClose the app, back up its documented save/profile directories, then select the app in Device Portal’s Apps manager and use Remove / Uninstall. Preserve your external game and save folders. Reinstalling a different package identity does not automatically migrate old data.
  2. Return to your retail gamesIn Developer Home → Quick actions choose Leave Dev Mode and restart. Read any cleanup option before confirming; leave deletion of sideloaded apps/data unselected when you want to preserve them. Routine mode switching does not require a factory reset.
  3. Return to development laterIn Retail Mode open Xbox Dev Mode and choose Switch and restart. This is different from permanently deactivating the console.
  4. Permanently deactivate only when intendedReturn to Retail Mode and use Xbox Dev Mode → Deactivate, or remove the matching console in Partner Center. Back up development data first and read the prompts. This removes developer activation; it is not the normal daily switching action.

  • Microsoft: permanent deactivation
